# FlowBoard 100 轮优化 — 测试记录

每轮交付独立 exe：`releases/FlowBoard-rNN.exe`（单文件，内嵌前端，无需装 Node）。
测试方法：双击 exe 或命令行 `FlowBoard-rNN.exe --host 0.0.0.0 --port 3000 --no-open`，
浏览器打开 `http://127.0.0.1:3000/`。每轮 exe 可用 `--version` 查看轮次版本。

## R06 — /qr 扫码访问页 ✅ 已构建待测（含 R02-R05 全部改动）

本轮包含 R02-R05 的全部改动（独立 exe，直接测最新即可，旧 exe 可留档对比）。

改动汇总：
- **R02 局域网 IP**：启动横幅自动检测并打印 `局域网访问: http://192.168.x.x:3000/`；
  分享链接（ShareDialog）自动用局域网 IP 而非 127.0.0.1（`FLOWBOARD_PUBLIC_HOST` 可覆盖）。
- **R03 横幅+版本**：框线横幅、`--version` 参数、控制台自动切 UTF-8 修中文乱码、数据目录相对路径。
- **R04 防火墙**：启动时检测 Windows 防火墙是否放行，未放行显示 ⚠ 提示；
  `allow-firewall.cmd` 增强（管理员校验、多端口）。
- **R05 自动换端口**：`--auto-port` 参数，端口被占自动 +1 重试（最多 +9）。
- **R06 /qr 扫码页**：`http://127.0.0.1:3000/qr` 或横幅里的"扫码访问"，
  页面显示指向局域网地址的二维码（MIT qrcode-generator），手机扫码直接打开编辑器。

请测试：
1. 启动 exe，横幅应显示"扫码访问 http://127.0.0.1:3000/qr"和真实局域网地址。
2. 浏览器打开 `/qr`，手机扫码（同一 Wi-Fi）应能打开编辑器。
3. 分享链接里应是 `192.168.x.x` 而非 127.0.0.1。
4. `FlowBoard-r06.exe --version` 显示 `FlowBoard 1.0.6`。
5. （可选）先占住 3000 端口再带 `--auto-port` 启动，应自动换到 3001。

已知待改进：`--auto-port` 换端口时横幅可能打印两次（不影响服务）。

## R16 — 修复服务端 Symbol.asyncIterator 崩溃 ✅（并入 r17 exe）
- 根因：pkg 打包的 Node 14 下 `for await...of req` 不兼容，POST 请求体解析即崩。
- 改为传统 data/end 事件模式。修复后 POST 接口（注册/登录/保存/分享）稳定。

## R17 — 图片保存失败修复 + 可视区裁剪 ✅ 已构建待测
- **图片保存失败根因**：粘贴/拖入图片时把「原图 base64」直接存进文档（显示缩到 480 但存储还是原图），
  大图（如 10MB 照片）→ 文档超 10MiB 上限 → 保存 413 失败。
- **修复**：图片实际压缩重绘（canvas 缩放 + JPEG 0.82 编码，透明图用 PNG），存储的才是小图；
  后端请求体上限 10MiB → 25MiB；保存失败时顶部明确提示原因。
- **可视区裁剪**：只渲染视口内的形状（旋转形状按外接包围盒 + 64px 余量），1000+ 元素流畅度提升。

请测试：
1. 粘贴一张大照片（几 MB）→ 画布显示正常 → 保存成功（不再失败）。
2. 画很多元素（100+）→ 缩放拖拽帧率是否更流畅。
3. 保存失败场景（如删掉服务）→ 顶部显示具体失败原因。
