# Dior 常驻本机语音助手

手机已安装独立 `dior-voice` 服务，OpenRC 默认启动。默认唤醒词是 **二狗**，
持续采集麦克风，使用本地关键词检测、流式识别、短模型对话和 Piper 扬声器输出。
联网查询是可选技能，基础控制与本地模型不依赖云端模型。

当前部署由 `dior-inference` 私有服务驻留一份 Qwen 模型，本机助手和登录后的
FlowBoard 网站共用。网站提供光标处听写、语音问答、授权项目/画布资料查询及播报，
详见 [网站接口说明](../../../frontend/docs/website-voice.md) 和 [共享桥](bridge/README.md)。
网页声音来自用户浏览器；手机麦克风仍由本机助手独立使用。

2026-10-03：已实测 Qwen3.5-0.8B 的 ARMv7 适配，并完成两种量化的独立 PC
语义对照，结果不足以替换默认主脑，详见 [候选评估](llm-qwen35-candidate/README.md)。
角色会话、播放确认提交、失败缓存提示、完整语句 ASR 和 Qwen2.5 的角色消息
适配已部署。生成 PCM 经实际 ASR、共享 TTS 和扬声器的问名字/空输入/异常恢复
测试通过，不能代替真人听感。当前延迟优化与实测范围见
[本地响应记录](evidence/LOCAL-LATENCY-20261003.md)。

Adreno 305 的 OpenCL 1.1 已补测真实 Qwen 权重矩阵：三种实现、六个算子用例
均通过数值校验，但本轮最快候选仍慢于现有量化 CPU 路径，正式模型未启用 GPU。
这不是整模型推理资格，也不代表所有 GPU 实现都不可能加速，详见
[OpenCL 算子源码与实测对照](llm-opencl-probes/README.md)。

专用关键词检测与生成音频联动测试已通过限定范围。用户随后确认单次“二狗”能完整
播完一次“我在，请说”；**远距离噪声、自由双讲、模型连续对话与长期待机仍未验收**。
不能将该确认或自动测试描述为小米电视级体验或零缺陷支持。
独立合成的短“二狗”有未命中样本，已保留失败记录。

## 使用

- “二狗”，等待“我在，请说。”，再说问题；同句命令也有对应处理路径。
- “二狗，音量最大 / 音量最小 / 音量调到五十 / 静音”。最小为 0，最大为 100。
- “二狗，现在几点？”、“二狗，你叫什么名字？”。
- “二狗，查一下 Linux”：只读网络来源，返回摘要和来源数据。
- “二狗，把唤醒词改成小猪哥”，等确认播报结束后说“确认”或“取消”。
  新词先经过 tokenizer 兼容检查、原生检测器确认，再原子保存，重启沿用。
- “二狗，停止”：取消当前回应；播报期间由当前声学唤醒词确认打断，VAD 声响本身不取消回应。

识别可能听错新名字。必须听清确认问题里的候选再确认；当前实测并未通过完整
自然改名句的端到端识别，因此不将这一条描述为真人改名已验收。
补测生成的“以后叫你小白”曾识别为“以后教你小白”或“以后叫你笑白”；后者经
确认保存了“笑白”，因此精确昵称拼写验收仍失败。有限“小/阿”昵称表达的同音兼容
仍只提出候选，不在未确认时保存；带“小/阿”的教学句也可能进入确认，应取消。

```sh
rc-service --nodeps dior-voice status
python3 /opt/dior-voice/runtime/voice_ctl.py
```

| 项目 | 实际证据 | 限制 |

| 唤醒 | 清晰合成语音前缀约 0.95 秒命中“二狗”；单字“二”不命中；改名后新词命中、旧词不命中 | 前缀来自同一已命中句，独立短合成词有失败，非真人输入 |
| 技能联动 | 注入生成 PCM，经过真实 KWS/ASR、mixer、speaker；最大/最小音量通过 | 数字注入不能代替真人通过麦克风输入 |
| 改名 | 内部文本提出候选，另一段真实 ASR 确认、检测器更新、设置持久化、新名身份回复通过 | 发起改词用内部文本，因为生成改名句仍有 ASR 错词；生产默认保留二狗 |
| 本地对话 | Qwen2.5-0.5B Q4_0，ARMv7 NEON/CPU；配置线程数见运行状态，本轮评估 2 线程 | 未使用 GPU，不保证秒答；旧版 3 线程网页约 5/14 秒属于历史样本 |
| 语音合成 | Piper 中文 huayan x_low；11 条固定短句 742144 字节只读缓存；常驻路径参见 TTS 记录 | 缓存提示的低延迟不是神经模型推理耗时，常驻合成也不等于首音频流式输出 |
| 联网 | 手机实际 HTTPS 查询获得来源与摘要 | 网络/DNS 失败会超时返回，不能保证每次联网成功 |
| 程序恢复 | 安装修复版实机运行；音频时钟中断触发仅语音服务重开 | 不重启网站、ASR 或穿透；真人和长时间可靠性仍需验证 |

不把节点存在、进程启动或契约通过冒充功能验收。

## 常驻与存储

麦克风和扬声器持续同卡运行；取消替换后续语音为零，不在采集线程执行会阻塞的
`pcm_drop/prepare`。完成与取消按实际硬件指针判断，支持 ALSA 指针循环。
XRUN 会报告错误，由仅本语音服务的 supervisor 重开双 PCM、重新训练回声滤波，
避免一次故障永久关闭打断能力。

ASR/回应任务各最多 1 个，捕获队列 50 帧，预录 25 帧；模型常驻一次加载。
会话由控制器在内存保留有界角色历史，仅成功播放的回答进入历史。
结束/取消/改名按代际清理；原生推理仅复用精确系统前缀，不保留用户或回答 KV 后缀。
不保存录音、转写或用户对话。
只有固定白名单提示音是只读资产，没有动态音频缓存。代码与模型不可由服务账号修改，
settings 最多 1 KiB。常规安装器保留一份程序回滚备份，不复制权重，日志不累计到磁盘。
本轮受控维护事务另保留有明确路径的程序备份，属于部署产物，不是每次对话增长的缓存。

本机只读状态 socket 为 `/run/dior-voice/control.sock`，没有公网 voice 端口、文本
注入或管理员控制接口。仅使用 audio/dior-asr 所需组，无 wheel/video 权限。
超过 65°C 暂停当前语音工作，沿用原有内核温控。
当前手机配置让模型问答/预填充先等待降到 45°C，已限制两核的动态语音合成
等待降到 50°C 再执行；运行中超过 65°C 仍取消。
冷却占原有有界任务槽，并受原 deadline/取消限制；固定缓存提示不启动推理。
四线程连续实测曾触发 67°C 取消，三线程也在并发测试中发生过温控取消。
本轮评估两线程并保留原温控，不改变内核频率；具体结果见本地响应记录。

时间、音量、名字和取消由有限规则处理，模型不执行任意 shell、路径或工具命令。
实际 LocalLanguageModel 的 intent 为 None；改名由对话规则加确认实现，TypedIntent
是扩展接口，不声称小模型已经自动解析或执行系统修改。

## 源码与准备

- [runtime](runtime/README.md)：控制器、流式 ASR、确认、代际取消、只读状态。
- [audio](audio)：板级 ALSA/SpeexDSP 适配与硬件资格配置。
- [kws](kws)：独立中文关键词检测器、动态关键词编译及固定来源。
- [llm](llm)：固定本机模型、原生 worker、适配器和构建输入。
- [tts](tts)：Piper/机械备用声、固定白名单缓存与来源。
- [install](install/README.md)：仅本 voice 命名空间的安装与程序恢复。
- [bridge](bridge/README.md)：共享模型、语音优先、网站隔离、温控及有界队列。

权重、第三方库、词典、生成语音和设备私有包不入 Git。准备工具保留固定来源、版本、
SHA 与许可资料；Huayan 数据集许可标记 Unknown，不能假定允许再分发权重。
安装需要先准备并验证各提供者资产；KWS 固定资产须放入 `/opt/dior-voice/kws` 后配置
OpenRC，再使用安装器验证并启动。安装器不承担网络下载和所有依赖的一键构建。
本轮不刷分区，不改内核、固件、GPU SDK、模型权重或网站业务数据。
ASR 只更新包内解码 worker/broker 的端点协议，保持原识别模型与库。
