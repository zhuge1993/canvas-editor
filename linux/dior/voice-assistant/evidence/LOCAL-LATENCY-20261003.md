# 本地语音响应修复与测量（2026-10-03）

用户明确选择完全本地并接受硬件限制。此轮不启用云端推理，不更换内核、分区、
固件或 ASR 权重。生成模型仍为 Qwen2.5-0.5B-Instruct Q4_0，ARMv7 NEON CPU。
Qwen3.5-0.8B 和后续 Qwen3-0.6B 的限定语义评估均不足以支持替换，分别见对应
候选目录及 `tests/QWEN3-LOCAL-SCREEN.md`。

## 已查明的问题

- 原 ASR 自动端点会在短句中间重置解码上下文，导致只送出“你”或残缺名字问题。
  仅拼接分段不能修复已丢失的声学上下文。语音助手现在在一个完整采集段内使用
  明确协商的 manual endpoint，finish 才结束；普通网页识别继续使用自动端点。
- 原模型适配路径丢失角色与助手名字上下文。新路径传递明确的 system/user/assistant，
  仅在真实播放完成后提交回复到会话历史；取消和未播出的回答不当作已说内容。
- 模型排队、温控取消、ASR 空结果或失败后没有稳定的结束提示。现在有有界的
  无输入、识别、回应和播放期限，失败使用已校验的本地固定提示，每次只播一次。
- 一次真人测试与后台文字基准发生竞争，日志记录了温控取消。该结果不能归因于
  单一模型速度。后续自动基准暂停语音监听，恢复后再进行真人测试。

## 第一轮真机修复验证

使用生成的 1.672 秒问题 PCM，数字输入实际 ASR，再经过控制器、共享 TTS 和
真实扬声器播放。麦克风帧被丢弃，声学唤醒被测试夹具绕过；没有保存真人录音。

| 项目 | 结果与边界 |
| --- | --- |
| 问名字 | 完整识别“你叫什么名字”，播完“我叫二狗。”，XRUN 为 0 |
| 无输入 | ACK 后约 17.683 秒完成一次“我还没听清，请再说一遍”，回到 IDLE |
| 注入 ASR 异常 | 约 2.840 秒完成一次相同提示，回到 IDLE |

问名字是有限身份技能，未调用 LLM。该样本从问题开始到播完为 7.640 秒；
从问题 PCM 结束到播放入队为 4.626 秒，到播完为 5.968 秒。
其中动态 TTS 为 3.665 秒，播放约 1.342 秒。不能把问题开始时间当作说完时间，
也不能把技能回复计入 LLM 速度。

## 常驻 TTS 原型实机

原 Piper 每次动态回答重新加载音色。原型用同一未修改的 Piper 进程连续读取 JSON，
使用一个已 unlink 的 tmpfs 临时文件接收完整 WAV；请求后截断为零，没有动态磁盘缓存。

| 生成请求 | 整体耗时 | 实际 PCM 时长 |
| --- | ---: | ---: |
| 首次“我叫二狗。” | 2.916 秒 | 1.272 秒 |
| 后续较长句 | 2.170 秒 | 2.376 秒 |
| 再次“我叫二狗。” | 1.005 秒 | 1.208 秒 |

RSS 约 41–43 MiB，子进程 FD 数为 4。稳定后空闲 5 秒 CPU ticks 未增加。
取消耗时 0.139 秒，子进程被回收，下一次请求以新 PID 恢复。
这是合成测试，没有播放或真人听感验收；三个请求也不是长时间内存稳定性证明。

Piper 日志的推理时间是累计值。原型报告的 1.075、3.224、4.216 秒不能当作
逐次耗时；正式源码明确记录累计值，并仅对同进程相邻计数计算差值。

## 最终 CPU 配置及回归

当前 LLM 为两线程；Piper 初始化后、每次输入前和返回音频前，将其所有线程
核验在最多两个 CPU 内。ORT 仍有四条线程，不能写成只有两条线程。
仅在 exec 前绑定主线程曾失败，ORT 会把工作线程重新放到 CPU 2/3；失败证据保留。
逐线程修复后的 140 个合成采样、560 条线程掩码均为 CPU 0–1，两句探针最高 57°C。
这同时增加了部分合成时间：冷短句 4.632 秒、暖较长句 5.829 秒，详见 TTS 记录。

模型/启动预填充准入温度为 45°C；动态 TTS 单独为 50°C；65°C 以上仍取消。
45°C 首次部署漏同步了 scheduler 的参数范围，readiness 拒绝后已自动回滚，随后
补齐两层校验与真实构造入口测试。所有维护操作仅重启 voice/inference，不刷分区。

网站也仅复用固定 system 的计算缓存，用户/项目/回答 KV 后缀仍在每次请求后移除。
将只读资料说明移入固定 system，动态串保留同样的净 180 UTF-8 字节项目资料；
限定词表样本的非缓存输入减少 10 tokens。截断标志按实际保留内容报告。

最终网站 HTTP → Unix socket → 实际模型/语音测试 8 项通过：匿名拒绝、能力查询、
精确项目计数、跨账户隔离、画布文字、普通模型问答、项目分析、音频返回。
本组未提供上传 PCM，所以不把网页 STT 计为通过；生成 PCM 的 ASR 链路另测。
普通问答 20.352 秒、项目分析 20.682 秒、音频返回 21.143 秒，均包含等待/冷却。
这组模型45/TTS45的连续样本最高 64°C，随后按两核 Piper 的资格把 TTS 单独改为50。

TTS50 的实际 ASR→扬声器补测完整播出“我叫二狗。”，XRUN 为 0。此例 ASR 正确
识别了“你叫什么名字”，走已有身份技能而未调用 LLM：问题 PCM 长 1.704 秒，
从问题开始到播完 9.520 秒，即从 PCM 结束到播放入队约 6.116 秒、到播完
约 7.816 秒。TTS 调用为 5.241 秒（包括等待），音频长 1.592 秒。
不能把它与识别成“教”而调用 LLM 的样本直接算作模型加速百分比。

一次此前完整模型路径样本仍用了 23.120 秒（从问题开始计），三项恢复检查虽通过，
延迟依然明显。以上结果说明响应和恢复路径可用，不代表无缝对话已达成。
失败版本的网页报告与温度曲线一并保留，最终报告为 `LOCAL-OPT-WEB-FINAL.json`。

自动测试后主语音服务已恢复 IDLE/ready，诊断文字追踪的生产参数关闭。
真人连续对话、嘈杂环境、自由插话以及长期待机仍需独立验收；不声称秒答、
高智力或与电视语音助手等同的体验。
